================================================================
Nika 研究环境部署指南（Intel / AMD 通用完整版）
================================================================

用途声明：本文档仅用于反作弊防御技术研究——在可控实验
环境中复现虚拟机指纹伪装方案，研究其检测面与防御措施。
请遵守当地法律法规及目标平台服务条款。

整体架构：
  +----------+    +----------+    +------------+    +--------------+
  | Linux PC | -> | QEMU/KVM | -> | Windows VM | -> | 目标游戏     |
  +----------+    +----------+    +------------+    +--------------+

三层伪装体系（研究核心）：
  1. QEMU 补丁层（qemupatch.sh）   → 设备 ID / SMBIOS / ACPI 表伪装
  2. 内核补丁层（kernelpatch 脚本） → CPUID / MSR / 计时反检测
  3. 固件补丁层（ovmfpatch.sh）    → OVMF/SMBIOS 固件级伪装

适用环境：
  - 宿主机：Fedora 44（KDE），内核 6.19.x
  - 硬件：双显卡机器（iGPU 留宿主机 + dGPU 直通给 VM）
  - 单显卡机器走 1.2 节 headless VNC 备选方案

----------------------------------------------------------------
0. 架构总览与平台差异速查
----------------------------------------------------------------

  | 项目                 | Intel                | AMD                          |
  |----------------------|----------------------|------------------------------|
  | CPU 虚拟化指令       | vmx                  | svm                          |
  | IOMMU GRUB 参数      | intel_iommu=on iommu=pt | amd_iommu=on iommu=pt     |
  | KVM 模块             | kvm_intel            | kvm_amd                      |
  | 核显解码驱动         | intel-media-driver   | mesa-va-drivers-freeworld(swap) |
  | qemupatch.sh 填写段  | *_8086               | *_1022（脚本按 CPU 自动选段）|
  | 内核补丁             | intel619.mypatch      | 仓库 AMD 对应补丁（自动选） |
  | XML cpu feature      | vmx                  | svm + topoext                |
  | split_lock_detect=off | 需要                | 不需要（加上无害）           |

键鼠方案说明（重要研究结论）：
  - 本指南采用 evdev 直通（VM 内是 QEMU 模拟的 USB HID 设备）
  - 不要用 virt-manager 的 USB Host Device 单设备直通——论坛
    研究人员实测其与封禁强相关（USB Host Device → 快速封禁；
    无 → 24h/30 场无封禁；PCI 控制器级直通 → 5h+ 无封禁）
  - 结论：输入设备走"模拟"不走"直通"，PCI 级（网卡/xHCI）直通安全

Phase 0：硬件验证（无需联网，先跑）


  - /dev/kvm 存在
  - IOMMU：Intel 有 "DMAR: IOMMU enabled" / AMD 有 "AMD-Vi" 相关行
  - 显卡：双显卡机器一块 iGPU + 一块 NVIDIA(10de) 或 AMD(1002) dGPU

1.6 锁内核（用精确列表，不要用 exclude=kernel*）

  踩坑：exclude=kernel* 会连 kernel-headers / kernel-devel
  一起锁死，后面编译 QEMU 时装不上依赖。直接用精确列表：

```bash
sudo tee -a /etc/dnf/dnf.conf << 'EOF'
exclude=kernel,kernel-core,kernel-modules,kernel-modules-extra,kernel-debug-core,kernel-debug-modules
EOF
grep exclude /etc/dnf/dnf.conf
```

  锁住的是启动内核本体；放开 kernel-headers / kernel-devel
  （仅是编译头文件，不影响启动内核）。

1.9 踩坑：libvirtd 重启后不自启（Fedora 41+ 模块化 daemon 冲突）

  Fedora 41+ 默认启用模块化 daemon（virtqemud、virtnetworkd
  等），开机时和老的 libvirtd 抢启动。解法：模块化全家禁掉：

```bash
sudo systemctl disable --now \
  virtqemud.service virtnetworkd.service virtstoraged.service \
  virtnodedevd.service virtnwfilterd.service virtsecretd.service virtinterfaced.service \
  virtqemud.socket virtqemud-ro.socket virtqemud-admin.socket \
  virtnetworkd.socket virtnetworkd-ro.socket virtnetworkd-admin.socket \
  virtstoraged.socket virtstoraged-ro.socket virtstoraged-admin.socket \
  virtnodedevd.socket virtnodedevd-ro.socket virtnodedevd-admin.socket \
  virtnwfilterd.socket virtnwfilterd-ro.socket virtnwfilterd-admin.socket \
  virtsecretd.socket virtsecretd-ro.socket virtsecretd-admin.socket \
  virtinterfaced.socket virtinterfaced-ro.socket virtinterfaced-admin.socket 2>/dev/null

sudo systemctl enable --now libvirtd.service
```

Phase 2：BIOS + KVM 模块 + VFIO 绑定 dGPU
----------------------------------------------------------------

2.1 BIOS 设置（README 3，开机进 BIOS）

  - 启用 Virtualization Technology：
    Intel 开 VT-d（VMX）；AMD 开 AMD-Vi（SVM）
  - 启用 "IOMMU"
  - 禁用 "Above 4G Decoding"（重要，直通 BAR 映射需要）

2.2 内核模块配置（README 3）

```bash
sudo tee /etc/modprobe.d/kvm.conf << 'EOF'
options kvm_intel nested=1
#options kvm_amd nested=1
options kvm ignore_msrs=0
softdep radeon pre: vfio-pci
softdep amdgpu pre: vfio-pci
softdep nouveau pre: vfio-pci
softdep nvidia pre: vfio-pci
EOF
sudo dracut -f
```

  AMD 机器：注释 kvm_intel 行，放开 kvm_amd 行。
  softdep 四行按实际情况保留（直通 NVIDIA 卡至少留 nouveau/nvidia 两行）。

2.3 找出 dGPU 的全部 PCI ID（README 3.1）

```bash
lspci -v | grep -i VGA          # 找显卡位置
lspci -n -s 01:00               # 按实际总线号，拿数字 ID
```

  说明：NVIDIA dGPU 可能有多个功能（VGA / HDMI 音频 /
  USB 3.1 控制器 / Type-C UCSI），记下全部 ID。
  vfio-pci.ids 只需填 VGA + 音频两个（USB/Type-C 功能
  即使不绑 vfio 也不影响，xhci_hcd 由 libvirt 接管管理）。

2.4 改 GRUB（README 3.1）

```bash
sudo cp /etc/default/grub /etc/default/grub.bak
sudo nano /etc/default/grub
```

  替换 GRUB_CMDLINE_LINUX 整行（ID 按上一步实际值替换）：

  Intel 平台：
  GRUB_CMDLINE_LINUX="nofb vfio-pci.ids=10de:xxxx,10de:yyyy split_lock_detect=off intel_iommu=on iommu=pt mitigations=auto"

  AMD 平台：
  GRUB_CMDLINE_LINUX="nofb vfio-pci.ids=1002:xxxx,1002:yyyy amd_iommu=on iommu=pt mitigations=auto"

  调优（对抗计时异常检测，配合 VM 的 cputune 绑核）：
  追加 cpuset.sched_load_balance=0 processor.max_cstate=1

  单显卡 headless 方案：vfio-pci.ids 可省略（宿主机本就在
  终端模式，可用 CTRL+ALT+F2/F3 切换 TTY）。

```bash
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
sudo reboot
```

2.5 验证 VFIO 绑定（关键）

```bash
lspci -k -s 01:00    # 总线号按实际
```

  判定：
  - VGA 和 Audio 两行显示 Kernel driver in use: vfio-pci
  - dGPU 的 USB 功能行显示 xhci_hcd 属正常（不加载为模块，
    由 libvirt 管理）

3.1 收集本机 PCI ID → 填 qemupatch.sh（README 7）

```bash
lspci -nn
```

  qemupatch.sh 会自动检测 CPU 厂商：Intel 用 *_8086 段，
  AMD 用 *_1022 段。把自己 lspci -nn 输出里对应类别设备的
  ID 填进对应段：

  | 变量（Intel / AMD）                | 对应 lspci 设备类别           | 示例   |
  |------------------------------------|-------------------------------|--------|
  | lpc_8086 / lpc_1022                | ISA bridge（芯片组 LPC/eSPI） | a30d   |
  | smbus_8086 / smbus_1022            | SMBus Controller              | a323   |
  | hdaudio_8086 / hdaudio_1022        | Audio device（PCH 声卡）      | a348   |
  | hdaname_8086 / hdaname_1022        | 该声卡的完整描述文本          | Cannon Lake PCH cAVS |
  | sata_8086 / sata_1022             | SATA AHCI / NVMe 控制器       | a353   |
  | rootport_8086 / rootport_1022      | dGPU 所在的 PCIe Root Port     | 1901   |
  | xhci_8086 / xhci_1022             | USB xHCI Host Controller      | a36d   |
  | hostbridge_8086 / hostbridge_1022 | Host bridge / DRAM Registers  | 3ec4   |
  | pcibridge_8086 / pcibridge_1022   | PCH PCI bridge / Shared SRAM  | a36f   |

  rootport 填法说明（README 作者示例）：
  dGPU 挂在 Root Port #8（a0bf）时填 a0b8（#8-7=#1 的 ID），
  即填"端口号减 7"的那个 Root Port ID，让 guest 枚举出
  正常的 #1 端口。若你的 root port 本身就是 #1，直接填真实值。

  填错反作弊伪装就露馅，必须用真机数据。

3.2 编译伪装 QEMU（README 7）

3.4 编译伪装内核（README 7.3）

```bash
sudo dnf install util-linux-script -y    # 脚本依赖（Fedora）
./kernelpatch619.sh
```

  - 脚本自动检测 CPU 厂商选补丁（Intel → intel619.mypatch；
    AMD → 仓库对应 AMD 补丁），不用手动选
  - 提示 CPU 架构优化时输入 native 回车
  - 编译 40-90 分钟。趁编译提前准备：
    Windows 10 20H1 ISO（win-10-2004-english-x-64 + KB4598291 补丁，
    README 有 archive.org 链接，国内慢可用多线程下载器拉）

  装三个 RPM（devel/headers 是给后面编译内核模块用的）：

```bash
cd linux-tkg/RPMS
sudo rpm -ivh kernel-<版本>_tkg_eevdf-1.x86_64.rpm \
            kernel-devel-<版本>_tkg_eevdf-1.x86_64.rpm \
            kernel-headers-<版本>_tkg_eevdf-1.x86_64.rpm
```

  踩坑：与已装的官方/仓库 kernel-headers 版本冲突时
  （比如装过 7.1.3），先移除再装：

```bash
sudo dnf remove kernel-headers-<旧版本> -y
# 再执行上面的 rpm -ivh（必要时加 --replacefiles）
```

  改 GRUB 追加 mitigations=auto（README 7.3），然后：

```bash
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
sudo reboot
```

  重启后验证：

```bash
uname -r    # 应为 6.19.x_tkg_eevdf
```

  踩坑：还是老内核 → GRUB 默认项没变，开机按 Esc 调出
  菜单手动选 tkg 内核进。

  踩坑（重要，会导致宿主机直接卡死）：新内核下 KVM 模块
  未自动加载时，启动 VM 会把宿主机卡死。开 VM 前必须确认：

```bash
lsmod | grep kvm
# 没有输出则：
sudo depmod $(uname -r)
sudo modprobe kvm_intel     # AMD 机器：sudo modprobe kvm_amd
```

  复查 VFIO（换内核必复查）：

```bash
lspci -k -s 01:00 | grep "Kernel driver"    # 仍为 vfio-pci
```

  变回 nouveau 了 → sudo dracut -f 后重启。

3.5 收集 SMBIOS 数据（建 VM 时要填真实值，README 2.1）

```bash
sudo dmidecode -t 1 -t 2 -t 3 -t 4 -t 17 > ~/smbios.txt
cat ~/smbios.txt
```

  （注意拼写是 dmidecode，别少个 m）
  需要 type 1（系统）/ 2（主板）/ 3（机箱）/ 4（CPU，含
  max-speed）/ 17（内存条）。

Phase 4：创建 Windows VM（README 2 + 2.1 + 2.2）
----------------------------------------------------------------

4.1 virt-manager 建 VM 骨架（README 2）

  Virtual Machine Manager → File → New Virtual Machine：
  1. Manual install → Forward
  2. 命名 win10 → Memory / CPU 按需 → Forward
  3. 取消勾选 [ ] Enable storage for this virtual machine → Forward
  4. 勾选 [x] Customize configuration before install → Finish
  5. Overview：Chipset 选 Q35，Firmware 选 OVMF_CODE_4M.secboot
     （或直接选编译好的 OVMF_CODE_4M.patched.qcow2，一步到位）
  6. NIC :xx:xx:xx：Device model 输入 rtl8125（手输），
     MAC address 填真机网卡 MAC → Apply
  7. Video QXL：Model 改为 VGA → Apply
  8. [Add Hardware] → Storage → Select or create custom storage →
     [Manage...] → [+] → 名称 win10、格式 Raw、Capacity 240 GiB →
     Finish → Cancel → Cancel
  9. [Begin Installation] → 立即 Virtual Machine → Shut Down →
     Force Off（只是先触发一次配置生成，不真的装）

4.2 XML 大改（README 2.1 + 2.2 + 7 + 7.1，共 12 刀，每刀贴完点 Apply）

  打开方式：VM → [Open] → View → Details → Overview → XML。

  刀 1：替换 <domain type="kvm"> 开头（SATA 控制器 + 磁盘）

```xml
<domain type="kvm" xmlns:qemu="http://libvirt.org/schemas/domain/qemu/1.0">
  <qemu:commandline>
    <qemu:arg value="-device"/>
```

5.1 键鼠 evdev 直通（README 4 + 4.1）

  1. 找出鼠标键盘（README 4）：

```bash
ls -l /dev/input/by-id/
# 认 event-mouse 结尾的是鼠标，event-kbd 结尾的是键盘
# 例：
# usb-Logitech_G102_...-event-mouse -> ../event5
# usb-SEMICO_USB_Gaming_Keyboard-event-kbd -> ../event14
```

  2. /etc/libvirt/qemu.conf 的 cgroup_device_acl 加入
     键鼠路径 + 对应的 event 节点（模板）：

```
cgroup_device_acl = [
    "/dev/null", "/dev/full", "/dev/zero",
    "/dev/random", "/dev/urandom",
    "/dev/ptmx", "/dev/kvm", "/dev/kqemu",
    "/dev/rtc", "/dev/hpet",
    "/dev/input/by-id/usb-<鼠标>-event-mouse",
    "/dev/input/by-id/usb-<键盘>-event-kbd",
    "/dev/input/event0",
    "/dev/input/event1",
    "/dev/input/event2",
    ...（把 by-id 里链接指向的 eventX 全列上）
    "/dev/kvmfr0",
    "/dev/userfaultfd"
]
```

  3. 重启 libvirtd：sudo systemctl restart libvirtd

  4. XML 里加 evdev 对象（追加到 </qemu:commandline> 前）：

```xml
    <qemu:arg value="-object"/>
    <qemu:arg value="input-linux,id=kbd1,evdev=/dev/input/by-id/usb-<键盘>-event-kbd,grab_all=on,repeat=on"/>
    <qemu:arg value="-object"/>
    <qemu:arg value="input-linux,id=mouse1,evdev=/dev/input/by-id/usb-<鼠标>-event-mouse"/>
```

  5. 加入 input 组（README 4.1）：

```bash
sudo usermod -aG input $USER
sudo reboot
```

  6. 使用：LEFT_CTRL + RIGHT_CTRL 在宿主机/VM 间切换输入。

  换不同型号键鼠时改 3 处：qemu.conf 的 ACL 路径、XML 的
  evdev 路径、（必要时）by-id 指向的 eventX 号。

5.2 网络方案（README 7.2，四选一）

  通用前置步骤：
  - Details 里删 USB Redirector 2、USB Redirector 1
  - Controller USB 0 → Model 手输 none → Apply
  - [Add Hardware] → PCI Host Device → 板载 USB 3.x xHCI
    Host Controller → Finish（整机 USB 控制器直通）
  - 删掉 NIC :xx:xx:xx（rtl8125 那块虚拟网卡）
  - 开 VM → 设备管理器 → 查看 → 显示隐藏设备 →
    Intel(R) 82574L Gigabit Network Connection → 卸载设备

  方案 A（推荐，实测干净）：PCI 直通板载网卡
  - [Add Hardware] → PCI Host Device → 板载有线网卡 → Finish
  - 宿主机用 WiFi 上网，VM 独占有线口（IP 由家里路由器分配）
  - VM 侧 Realtek 驱动 Win10 自带

  方案 B：rtl8125 虚拟网卡（README 7.2.1b）
  - [Add Hardware] → Network → MAC 填真机网卡 MAC →
    Device model 手输 rtl8125 → Finish
  - qemupatch.sh 已把 QEMU 的 e1000 模拟改成 RTL8125 2.5G

  方案 C：USB 网卡（README 7.2.1a）
  - USB 网卡插在直通给 VM 的 xHCI 控制器口上，即插即用

  方案 D：virtio（README 7.2.1c，性能最好但步骤多）
  - 下载 virtio-win.iso（fedorapeople.org 最新版）
  - XML 追加 virtio ISO 光驱：

```xml
    <qemu:arg value="-drive"/>
    <qemu:arg value="file=/home/用户/Downloads/virtio-win.iso,format=raw,read-only=on,if=none,id=drive-sata1-1"/>
    <qemu:arg value="-device"/>
    <qemu:arg value="ide-cd,bus=device-sata1.1,drive=drive-sata1-1,id=sata1-1"/>
```

  - 删 vars.sh，重跑 qemupatch.sh 和 ovmfpatch.sh
  - 下载 virtio.cmd 到 VM 桌面 network 文件夹并运行（从
    CDROM 拷贝必要文件）
  - 关 VM → [Add Hardware] → Network → Device model: virtio →
    MAC 填真机 MAC → Finish
  - 开 VM → 设备管理器从 network 文件夹装 virtio 网卡驱动
  - 管理员 CMD 关测试签名后重启：bcdedit /set testsigning off

7.1 EDID 伪装（README 7.5）

  背景：EAC 封禁研究表——公网 IP / 路由器 MAC / 显示器
  EDID 都会被标记，显示器 EDID 是 HWID 的重要组成。

  1. 下载 EDWriter（monitortests.com 论坛）
  2. EDWriter → Read EDID → Save file → edidfile.bin
  3. 下载 edidpatch.cmd 到 EDWriter 目录（VM 内）
  4. 运行：edidpatch.cmd edidfile.bin
  5. 把改过的 EDID 写入 Dummy/Passthrough（HDMI 欺骗器）：
     采集卡接欺骗器，显示器指纹即改变

  采集卡与欺骗器对照表（README 7.5）：
  | 采集卡                | 欺骗器                     |
  |-----------------------|----------------------------|
  | HD60 S+               | Fueran HDMI-2K-2P          |
  | HD60 X                | Fueran HDMI-2K-2P          |
  | 4K60 Pro / MK.2       | Fueran HDMI-2K-4K          |

7.2 GPU 伪装（README 7.6，实测 51x→58x 有效）

  1. VM → Details → 每个直通的 PCI Host Device →
     取消勾选 [ ] ROM BAR → Apply
  2. nvidia-smi -L 记下旧 UUID
  3. 开 VM，游戏前先跑一次 nika
  4. 再看 nvidia-smi -L → UUID 已变化

7.3 网络伪装（README 8，研究向）

  - 本机与 ISP 路由器之间再加一级路由器（DD-WRT/OpenWRT）
  - 关键点：要定期改的是 LAN 口 MAC（ARP 表 arp -a 里收集
    的那个），不是 WAN/WLAN MAC
  - 本地买路由器（认准品牌/型号/版本号刷机包）
  - DD-WRT 改 LAN MAC（telnet 后）：

```shell
nvram set lan_hwaddr=XX:XX:XX:XX:XX:XX
nvram get lan_hwaddr
nvram commit
reboot
```

  - DD-WRT → Setup → MAC Address Clone → 勾选 Enable →
    克隆 WAN MAC 和 Wireless MAC → Save → 重启路由器

  时机建议（实测结论）：网络伪装和 EDID 在未被封禁时
  不必启用；封禁后再上。

Phase 8：日常更新与重编译
----------------------------------------------------------------

8.1 判断要不要重编译

```bash
cd ~/nika        # 仓库目录
git pull
# 看关键文件最近是否有变更：
git log --oneline -10 -- intel619.mypatch qemupatch.sh kernelpatch619.sh ovmfpatch.sh
```

  | 仓库更新了什么                                  | 是否重编译 |
  |-------------------------------------------------|------------|
  | intel619.mypatch / AMD 补丁 / kernelpatch619.sh | 重编内核   |
  | qemupatch.sh                                    | 重编 QEMU  |
  | ovmfpatch.sh                                    | 重编 OVMF  |
  | nika.ini / README / 文档类                      | 不用       |

  注意：如果 qemupatch.sh 上游改动和你本地填写的
  *_8086 / *_1022 设备 ID 冲突，git 合并时保留你本地的真机值。

8.2 重编 QEMU

```bash
cd ~/nika
sudo rm -rf qemu/build      # 清残留
./qemupatch.sh
ls -lh /usr/local/bin/qemu-system-x86_64   # 日期更新 = 成功
```

  - vars.sh 保留 → 设备 ID 不变，XML 不用改
  - VM 完全关机再启动，才用上新二进制

8.3 重编内核

```bash
cd ~/nika
./kernelpatch619.sh          # 架构优化照旧输 native
cd linux-tkg/RPMS
sudo rpm -ivh kernel-*.rpm   # 版本升级冲突时改用 rpm -Uvh 或先卸旧版
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
sudo reboot
```

  重启后必做三件事：
  1. uname -r 确认进了新 tkg 内核
  2. lsmod | grep kvm —— 没有就 depmod + modprobe
     （kvm_intel / kvm_amd），否则开 VM 宿主机会卡死
  3. lspci -k -s 01:00 确认仍是 vfio-pci

  若宿主机侧编译了 memflow-kvm（dkms），换内核后需
  modprobe memflow 或按 6.6 重装 dkms 包；只走 QEMU 通道
  读取 VM 内存则不受影响。

8.4 重编 OVMF

```bash
cd ~/nika
./ovmfpatch.sh
```

  已有 VM 引用的是同一路径的 OVMF_CODE_4M.patched.qcow2，
  VM 关机后下次启动即生效。注意：若 VARS 文件也是直接引用
  /usr/share/edk2/ovmf/ 下的模板，重跑脚本可能重置启动项
  和密钥——更新前先备份该 VARS 文件，VM 关机状态下更新。

附录 B：VMAware 2.6 检测项与对策（实测全绿）
----------------------------------------------------------------

  | 检测项               | 原理                            | 对策                                   |
  |----------------------|---------------------------------|----------------------------------------|
  | CPUID signatures     | CPUID hypervisor 位 / MSR 行为  | 刀 5 + kvm hidden + 内核补丁 + vmware metadata |
